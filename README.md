# M5StickC ナースコール

```
[StickC] --Wi-Fi--> [ルーター] --Wi-Fi--> [Core2] --(任意) HTTPS--> ntfy.sh --> スマホ
 ディープスリープ                          常時起動(USB)
```

## 必要なもの
- Arduino IDE + ボードパッケージ「M5Stack」(arduino-esp32 2.x / 3.x どちらでも可)
- ライブラリ「M5Unified」(ライブラリマネージャで検索してインストール)

## 書き込み手順
1. `nurse_call_core2` の `WIFI_SSID` / `WIFI_PASS` を設定して Core2(ボード: M5Core2)に書き込む
2. Core2 の待機画面に出る **IP アドレス** を確認
   - IP が変わらないように、ルーターの「DHCP 予約(固定割り当て)」に登録するか、`USE_STATIC_IP = true` にする
3. `nurse_call_stickc` の `WIFI_SSID` / `WIFI_PASS` / `CORE2_IP` / `DEVICE_NAME` を設定して StickC に書き込む
   - `CORE2_IP` が分からない・変わっても、ブロードキャストでも送るので同じネットワーク内なら届く(ルーターがブロードキャストを止めている場合を除く)

StickC を複数台使う場合は、`DEVICE_NAME` を変えてそれぞれ書き込むだけです。

## 使い方
- StickC: メインボタン(M5ロゴのボタン)を **1秒長押し** → 「呼び出しました」(緑)が出れば Core2 に届いています。
  - 「Wi-Fi接続失敗」(赤): ルーターの電波が届いていない / SSID・パスワード違い
  - 「届きません」(赤): Wi-Fi は繋がったが Core2 から応答なし(Core2 の電源・IP を確認)
- Core2: 画面が赤く点滅し、チャイム＋振動。**画面か下の3ボタンをタッチで停止**。待機画面に直近5件の履歴。
  Wi-Fi が切れていると待機画面に赤で警告が出ます。

## スマホ通知(任意)
1. スマホに **ntfy** アプリ(iOS / Android)を入れる
2. 他人に推測されないトピック名(例 `nursecall-k3x9q2`)を決めてアプリで購読
3. `nurse_call_core2.ino` の `NTFY_TOPIC` に同じ名前を設定
   - ntfy.sh 経由なのでインターネット接続が必要です。トピック名を知っている人は誰でも読めるので推測困難な名前に。

## 仕組みと省電力のポイント
- StickC は普段ディープスリープ。BtnA(GPIO37)の ext0 割り込みで起床。
- 長押し判定は `M5.begin()` より前に行うので、短押し(誤操作)なら画面も Wi-Fi も点けずに即スリープへ戻る。
- 前回つながったルーターのチャンネルと BSSID を RTC メモリに覚えておき、次回はスキャン無しで接続(失敗したら通常接続にフォールバック)。
- `USE_STATIC_IP = true` にすると DHCP 待ちも省けて、起きている時間がさらに短くなる。
- UDP で送って Core2 の ACK を確認、届かなければ最大10回再送。
- 初代 StickC は電池が 80mAh と小さく、基板構成上ディープスリープでも消費はゼロにはなりません。実際の持ちは使ってみて電池残量(電源投入時に表示)を確認してください。
